# chunk_saver — бенчмарк алгоритмов хранения чанков Minecraft

Rust-приложение: читает **реальные миры** из `.minecraft/saves`, выгружает чанки
(современный 1.18+ формат и легаси 1.12), прогоняет наборыови компрессии,
проверяет round-trip корректность и показывает результаты в веб-UI с
**двухосевым графиком** (размер ↔ скорость).

## Запуск

```bash
# 1) Бенчмарк → JSON в stdout
cargo run --release --bin chunk_saver -- bench --max-chunks 512

# 2) Веб-интерфейс (по умолчанию порт 8095, НЕ 8080)
cargo run --release --bin chunk_saver -- serve --port 8095

# параметры
#   --world DIR      путь к сейву или папке saves (default: /mnt/D/lol/.minecraft/home/Fabric 1.21.11/saves)
#   --max-chunks N   сколько чанков сэмплировать (default 512)
#   --seed S         детерминированная выборка
#   --port P         порт HTTP (default 8095; 8080 запрещён)
```

После `serve` откройте http://localhost:8095 — график, таблица, карточки
«лучшее сжатие» и «самый быстрый encode», переключатель между оригинальными
чанками и чанками после удаления невидимых блоков.

## Что внутри

| Модуль | Назначение |
|---|---|
| `src/nbt.rs` | парсер NBT (big/little endian), все типы тегов |
| `src/mca.rs` | чтение region-файлов (.mca), zlib/gzip/uncompressed |
| `src/chunk.rs` | модель чанка; разбор современного и легаси форматов; `prune_interior` — удаление внутренних (невидимых) блоков |
| `src/world.rs` | выборка чанков из миров; глобальный реестр блоков; списки блоков на биом (до 255 блоков) |
| `src/codec/*` | алгоритмы хранения (см. ниже) |
| `src/bench.rs` | замер encode/decode, размеров; проверка round-trip |
| `src/web.rs` + `web/index.html` | axum-сервер + самодельный SVG-график (без внешних зависимостей) |

## Алгоритмы (реестр в `src/codec/mod.rs`)

- `raw` — блок = u32 без сжатия (эталон скорости/размера).
- `rle-column` — RLE по вертикальным колонкам x,z.
- `minecraft` — **стандартный формат Minecraft** (1.18+): палитра состояний
  блоков + бит-упакованные long-массивы, по секциям 16×16×16.
- `layered` — предложенный тобой формат со слоями и заголовком в 1 байт.
  Варианты: `layered` (слой 1 блок, 16×16), `layered-h4`, `layered-h16`
  (толщина слоя 4/16), `layered-32` (тайлы 2×2 чанка, слой 32×32).
- `mc+deflate6/12`, `layered+deflate12` — медленная, но плотная упаковка
  (zlib поверх другого кодека) — «для диска».

### Формат `layered` (по ТЗ)

Каждый слой — заголовок 8 бит: `тип (2 бита) + остальное по типу`.

1. `solid` — весь слой одинаковый: биты 5–4 = ширина ID
   (0 → 4 бита, 1 → 8, 2 → 16, 3 → 32), далее сам ID.
2. `adaptive map` — биты 5–3 = ширина индекса (0 → 1 бит … 5 → 32 бита),
   бит 2 = есть локальная палитра, биты 1–0 = источник списка
   (0 глобальный, 1 биомный, 2 палитра слоя, 3 зарезервирован).
3. `replicator` — биты 5–4 = ширина количества копий
   (0 → 4 бита, 1 → 8, 2 → 12 (4 из заголовка + байт), 3 → 20);
   биты 3–0 = старшая тетрада первого run. Далее идёт байт ширины ID и run-ы.
4. `repeat` — биты 5–4 = режим: 0 = копия предыдущего слоя, 1 = периодическая
   копия слоя n−2 (нулевой payload).

Кодировщик для каждого слоя считает стоимость всех типов и выбирает минимальную.
Всё после фиксированного заголовка — единый битовый поток.

### Удаление невидимых блоков

`prune_interior` заливает воздух от 6 граней чанка (BFS) и оставляет только
блоки, касающиеся достижимого воздуха; остальные заменяются воздухом
(аналог Bobby-кэша). Для каждого алгоритма считается и «оригинальный» датасет,
и «обрезанный» — видно, насколько сжатие выигрывает от оклюзии.

## Результаты (512 чанков из реальных миров, см. `report.json`)

| Алгоритм | оригинал, B/чанк | после оклюзии, B/чанк | encode | decode |
|---|---:|---:|---:|---:|
| raw | 24770 | 24770 | ~9 мкс | ~14 мкс |
| rle-column | 1311 | 962 | ~22 мкс | ~10 мкс |
| minecraft (стандарт) | 1014 | 53 | ~100 мкс | ~4 мкс |
| layered | 364 | 225 | ~90 мкс | ~53 мкс |
| layered-h4 | 367 | 207 | ~82 мкс | ~52 мкс |
| layered-h16 | 416 | 203 | ~84 мкс | ~53 мкс |
| layered-32 | 558 | 195 | ~85 мкс | ~55 мкс |
| mc+deflate12 | 132 | 48 | ~132 мкс | ~12 мкс |
| layered+deflate12 | 130 | 35 | ~101 мкс | ~59 мкс |

Выводы на этом датасете: стандартный Minecraft-формат в среднем сжимает
хуже layered (палитра на секцию + 4-битовый мин-бит), но его **decode почти
бесплатный**; лучший размер даёт `layered+deflate12`; после удаления
невидимых блоков всё сжимается в разы (чанки становятся почти пустыми).

## Как добавить свой алгоритм

Полная спецификация — в **`ADD_ALGORITHM.md`** (её можно целиком отдать
агенту/LLM): структура файла кодека, трейт, контракты round-trip, примеры,
чек-лист тестов и частые ошибки. Коротко:

1. Реализуйте `trait Codec` в новом файле `src/codec/my_algo.rs`
   (`encode_tile` / `decode_tile`, + `group_size` для тайлов, например 4 для 32×32).
2. В этом же файле объявите `pub const REGISTRY: &[RegistryEntry]` с id, именем,
   категорией и описанием. **Правки `src/codec/mod.rs` не нужны** — `build.rs`
   сам сканирует каталог `src/codec/` и подхватывает новый файл.
3. Проверьте: `cargo test`, `cargo run --release --bin chunk_saver -- bench --max-chunks 512`
   (round-trip должен дать `ok=true`), затем `serve`.
4. Готово — алгоритм появится в бенчмарке, отчёте и на графиках автоматически.
   Так же легко подключить десятки вариантов, сгенерированных на arena.ai.
