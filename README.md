# chunk_saver — бенчмарк алгоритмов хранения чанков Minecraft

Rust-приложение: читает **реальные миры** из `.minecraft/saves`, выгружает чанки
(современный 1.18+ формат и легаси 1.12), прогоняет наборы алгоритмов компрессии,
проверяет round-trip корректность и показывает результаты в веб-UI с
**двухосевым графиком** (размер ↔ скорость).

> Проект сделан с активным использованием AI-агентов.

## Запуск

```bash
# 1) Бенчмарк → JSON в stdout
cargo run --release --bin chunk_saver -- bench --max-chunks 512

# 2) Веб-интерфейс (по умолчанию порт 8095)
cargo run --release --bin chunk_saver -- serve --port 8095
```

Параметры:

| Флаг | Описание | По умолчанию |
|---|---|---|
| `--worlds-dir DIR` | путь к сейву или папке saves | `~/.minecraft/saves` |
| `--exclude NAME` | исключить миры, в имени которых есть NAME (можно повторять) | — |
| `--max-chunks N` | сколько чанков сэмплировать | `512` |
| `--seed S` | детерминированная выборка | `1` |
| `--host H` | адрес прослушивания для `serve` | `127.0.0.1` |
| `--port P` | порт HTTP | `8095` |

Если ваш `.minecraft` лежит не в `~/` (например, на отдельном диске),
укажите путь явно:

```bash
cargo run --release --bin chunk_saver -- bench --worlds-dir "D:/games/.minecraft/saves"
```

Исключите миры через `--exclude` (повторяемый флаг):

```bash
cargo run --release --bin chunk_saver -- bench --exclude creative --exclude test
```

После `serve` откройте http://localhost:8095.

## Что внутри

| Модуль | Назначение |
|---|---|
| `src/nbt.rs` | парсер NBT (big/little endian), все типы тегов |
| `src/mca.rs` | чтение region-файлов (.mca), zlib/gzip/uncompressed |
| `src/chunk.rs` | модель чанка; разбор современного и легаси форматов; `prune_interior` — удаление внутренних (невидимых) блоков |
| `src/world.rs` | выборка чанков из миров; глобальный реестр блоков; списки блоков на биом |
| `src/codec/*` | алгоритмы хранения |
| `src/bench.rs` | замер encode/decode, размеров; проверка round-trip |
| `src/web.rs` + `web/index.html` | axum-сервер + SVG-график (без внешних зависимостей) |

## Алгоритмы

Структура `src/codec/`:

| Папка | Что внутри |
|---|---|
| `base/` | эталонные/референсные алгоритмы |
| `custom/` | проверенные кастомные кодеки |
| `disabled/` | отключённые (код сохранён) |
| `sandbox/` | новые реализации для теста — автоматически попадают в бенчмарк |
| `deflate.rs` | обёртка zlib |

Базовые:

- `raw` — блок = u32 без сжатия (эталон скорости/размера)
- `rle-column` — RLE по вертикальным колонкам x,z
- `minecraft` — стандартный формат Minecraft (1.18+): палитра + бит-упакованные long-массивы по секциям 16×16×16
- `layered` — формат со слоями и заголовком в 1 байт
- `mc+deflate6/12`, `layered+deflate12` — zlib поверх другого кодека

Новые алгоритмы добавляются в `src/codec/sandbox/` (см. `sandbox/README.md` и `ADD_ALGORITHM.md`).

### Формат `layered`

Каждый слой — заголовок 8 бит: `тип (2 бита) + остальное по типу`.

1. `solid` — весь слой одинаковый: биты 5–4 = ширина ID (0 → 4 бита, 1 → 8, 2 → 16, 3 → 32), далее сам ID.
2. `adaptive map` — биты 5–3 = ширина индекса, бит 2 = есть локальная палитра, биты 1–0 = источник списка.
3. `replicator` — RLE-подобные run-ы с переменной шириной.
4. `repeat` — копия предыдущего слоя или слоя n−2.

Кодировщик для каждого слоя считает стоимость всех типов и выбирает минимальную.

### Удаление невидимых блоков

`prune_interior` заливает воздух от 6 граней чанка (BFS) и оставляет только блоки, касающиеся достижимого воздуха; остальные заменяются воздухом. Для каждого алгоритма считается и «оригинальный» датасет, и «обрезанный».

## Как добавить свой алгоритм

Подробно — в **`ADD_ALGORITHM.md`**. Коротко:

1. Реализуйте `trait Codec` в новом файле `src/codec/sandbox/my_algo.rs`.
2. Объявите `pub const REGISTRY: &[RegistryEntry]`.
3. Проверьте: `cargo test` и `cargo run --release --bin chunk_saver -- bench --max-chunks 512` (должно быть `ok=true`).
4. Алгоритм автоматически появится в бенчмарке и на графиках.
