# Песочница новых кодеков (sandbox)

Сюда кладите **новые реализации** алгоритмов для теста. Ничего больше
настраивать не нужно: `build.rs` сканирует эту папку автоматически, и любой
файл с `pub const REGISTRY: &[RegistryEntry]` сразу появляется в бенчмарке,
JSON-отчёте и веб-UI.

## Как пользоваться

1. Скопируйте `template.rs` в новый файл, например `src/codec/sandbox/my_algo.rs`.
2. Реализуйте `encode_tile` / `decode_tile` (трейт `Codec`, см.
   `src/codec/mod.rs` и `ADD_ALGORITHM.md`).
3. Заполните и раскомментируйте `REGISTRY` в конце файла: `group` и
   `description` указываются только там (в трейте `Codec` метода `description()`
   нет).
4. Проверьте round-trip:

   ```bash
   cargo test
   cargo run --release --bin mc-chunk-bench -- bench --max-chunks 512
   ```

   В отчёте у нового алгоритма должно быть `ok=true`.

5. Решите судьбу алгоритма:

   - **Удался** → переместите в `src/codec/custom/`:
     `git mv src/codec/sandbox/my_algo.rs src/codec/custom/my_algo.rs`
   - **Не удался** → удалите файл. Можно оставить на время
     (например, закомментировав `REGISTRY`), если хочется сохранить код.

## Правила

- Один файл — один алгоритм (или один набор вариантов одного алгоритма).
- Не редактируйте кодеки из `base/` и `custom/` ради экспериментов —
  для этого есть песочница.
- Если алгоритм получился медленным, но плотным — это нормально,
  в `custom/` ему тоже есть место.
